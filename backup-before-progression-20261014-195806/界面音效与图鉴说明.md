# 界面、音效与图鉴更新

2026-10-13。保持原来的米白底色、细边框、文字卡片、小按钮；没有加入图片素材或背景音乐。

## 先体验这几步

1. 用 Godot 4.6 打开 project.godot，按 F5。进入后厨，打开食材箱，取番茄和鸡蛋。
2. 拖动时，卡片轻微抬起、有柔和阴影；拖到可接受的工具或食材上，目标变为浅绿色。叠放成组后拖到炒。
3. 第一次制作番茄炒蛋，成品短暂放大并呈现暖金色，桌面下沿依次显示菜名、标签与“已收录图鉴”。提示不接管鼠标，不暂停游戏，约1.45秒收起。再次做同样的菜不重复发现。
4. 点侧栏“图鉴”。已发现料理排在前面；未发现条目隐藏菜名与配方，只显示类别。选择分类，或查看“我的创作”。点击已发现料理可以看不同制作记录。
5. 先切材料，再炒同一道菜，会在同一菜名下增加制作记录，不会重复增加发现数量。自由组合出来的新名字会收入“我的创作”。
6. 料理拖到“出餐！”，切回餐厅，可看到三格出餐台。扩建后显示六格。
7. 点侧栏“设置”，调音量、静音或试听；可开启“减少动态效果”。窗口继续支持标题栏拖动和右上角□切换尺寸。
8. 最新版本从开始界面选择存档，金币、库存、图鉴等在每天打烊后保存；声音设置即时保存。详见《开始界面与存档说明.md》，本文其余部分记录此前的界面与音效实现。

## 界面改动

标题与日期、金币分开排列，避免靠空格对齐。按钮统一边距、四像素圆角与悬停/按下颜色。当前页面仍是浅绿底。图鉴未发现条目使用淡灰色，不与选中页面混淆。

卡片增加轻阴影，成品左侧有暖金色边线。详情继续在原地展开，材料分行、标签每行两项；再次点击关闭。拖拽时放大约2.5%，松手后回弹并恢复原尺寸。无效拆分有短促轻晃与错误提示。

短操作提示改为鼠标附近的小浮窗，3.4秒后淡出，长提示6秒。小浮窗不拦截鼠标，下一次点击卡片或按钮即收起。帮助、图鉴、升级等长内容仍在可拖动窗口内。

出餐台从抽象文字区域改为有编号的空位。农场与畜棚收集时增加向箱子飞入的文字影子；物品只结算一次，影子不接受鼠标操作。

## 本次新增文件

### feedback.gd：音效和短动画

`_ready()` 加载 audio 内19个 WAV 音效，建立6个播放节点，并创建非阻挡的短提示、新料理发现提示。

`play()` 先检查静音与音量，再限制同一种声音90毫秒内不重复播放。最多同时播放6个声音，超过时丢弃本次声音，避免连续收获叠成噪声。普通音效音高有小幅随机变化，发现旋律固定。

`pulse()` 使用 Godot 自带 Tween 在0.18秒内恢复卡片大小、0.3秒内恢复颜色。新的反馈会结束同一卡片未完成的旧动画。`reveal_card()` 为新发现成品加暖金色和稍大的回弹。

`announce()` 将新菜加入数组，`show_next()` 播完一条再取下一条，所以连续发现不会叠在一起。发现栏位于桌面下沿，鼠标穿透，不挡出餐和垃圾桶操作。

`preview()` 检查拖动食材、种子或收获物的有效目标；`highlight()` 只保留当前一个高亮，离开或切页时还原。厨房和餐厅的具体判断分别在其页面脚本的 `preview_drop()`。

`collect()` 创建一个临时文字影子飞向箱子。原物品立即进入库存并删除，动画完成后影子也删除，避免动画期间重复拖入造成多次收入。

音效为这次制作的短合成音，适合当前文字原型；不是实录厨房声音。audio 文件可直接替换为同名 WAV。没有下载第三方素材。

### catalog.gd：发现记录与保存

`discover()` 按配方 key 去重。不同 key 可以有同一个菜名；这种情况仅新增做法记录，不再次播放发现动画。`count_known()` 对照 food_data.json 中的30道具名料理统计进度。

`build()` 在现有管理窗口中创建分类、列表和详情。未发现菜名不写入列表文字，也不能点开配方。自由组合名称单独收入“我的创作”。详情按每份食材的实际处理历史和最终烹饪方式展示，可照着复现。

`save_data()` 先写临时文件，再替换正式文件，保留上一个文件为 .bak。`load_data()` 遇到无法解析的主文件会读取备份；逐条校验材料与处理历史，跳过损坏条目，重新计算名称、权重与基础价。

图鉴与菜谱共享制作记录；重启后发现过的做法会出现在菜谱中，但不会自动上架，售价调整回到基础值。图鉴恢复不重新播放发现动画。

保存位置使用 Godot 的 `user://cooking_catalog.json`，通常位于 Windows 的 `%APPDATA%/Godot/app_userdata/文字料理 · 工作台原型/`。这是项目外的用户数据；正常替换游戏代码不会清空它。测试使用独立的 test_catalog.json，不影响正式图鉴。

| barn.gd | 产物音效、收集飞入动画 | `spawn_product()`、`drop_product()` |

主场景仍只有 Main 节点。运行时新增 Feedback 和 Catalog 两个普通节点；反馈面板与原有管理窗口由脚本创建。没有增加事件总线或复杂框架。

## 常改参数

- 颜色：main.gd 的 `style_button()`、card.gd 的 `refresh()`、feedback.gd 的 `make_panel()`。
- 拖动阈值：card.gd 的 `DRAG_DISTANCE`，目前仍为8像素。
- 音效默认音量：feedback.gd 开头的 `volume = 0.55`。设置窗口保存过的音量优先。
- 同时播放上限：feedback.gd `_ready()` 中的 `range(6)`。
- 动画速度：feedback.gd `pulse()`、`show_next()` 中各 Tween 的秒数。
- 图鉴分类：catalog.gd 的 `category()`；具名菜仍在 food_data.json 中维护。

## 验证方法

test_polish.gd 检查音效加载、重复与变体发现、分类、隐藏配方、静音、播放数量、图鉴写入/恢复、窗口与出餐台。运行时必须带 `-- --test-mode`。test_catalog_reload.gd 使用 `-- --test-mode --test-reload`，检查另一个游戏进程能恢复测试图鉴且不会重播发现。先运行前者，再运行后者。

test_cooking.gd 继续验证原有79项料理与经营交互；test_live.gd 验证真实时间的成长和顾客到访。测试截图只用于核对排版，不代表你的图鉴已经解锁。

下一步建议先试玩一轮，重点感受提示长度、音量和拖拽回弹，再决定是否需要更轻的反馈。每日经营存档现已实现，参见《开始界面与存档说明.md》。
