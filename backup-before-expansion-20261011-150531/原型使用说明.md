# 文字料理：初步原型使用说明

## 1. 打开和试玩

用 Godot 4.6 打开本目录的 `project.godot`，按 F6 运行当前主场景，或按 F5 运行项目。主场景已设为 `main.tscn`。窗口为 1280×720 横屏，使用兼容渲染模式。

最容易验证的一道菜：

1. 默认在餐厅页。把番茄的**卡片中心**拖到「榨」的矩形里面松手。
2. 番茄变成 `番茄 [榨]`，自动放到工具旁的空位。
3. 点击右上角「食材 +」，再点击「番茄 +」，获得另一份番茄。
4. 把新番茄中心拖到刚榨过的番茄上松手，形成食材组。不同处理状态分行显示，便于检查；同名同状态显示 `x2`。
5. 还可以把鸡蛋拖上去，加入该组。
6. 把整组中心拖到「炸」上，得到 `未知料理 / 超浓 / 细腻 / 酥脆`。
7. 单击料理查看说明，再点一次关闭。移动不到 8 像素仍算单击。
8. 拖动「切」到右侧，工具会停在左区边界。点击农场、畜棚查看占位页，再回餐厅，卡片保留。
9. 点击「重置」重新测试；关闭游戏后不会保存，本原型尚未加入存档。

只支持鼠标左键。工具可以在左区自由摆放；食材和料理可以在整个桌面移动。工具彼此可以覆盖，遇到覆盖可先把上面的拖开。拖入目标按卡片中心判断，不是只擦到边就合并。

## 2. 文件与场景树

- `project.godot`：窗口大小、兼容渲染、默认主场景。
- `main.tscn`：只有一个 Main 根节点，挂 `main.gd`，可直接运行。
- `main.gd`：创建界面、添加卡片、组合、处理、烹饪、说明、页面切换。
- `card.gd`：每张卡片的外观、文字、点击和拖动。
- `test_workbench.gd`：开发检查脚本，正常运行不会加载，也不必修改它。

为了减少场景文件，界面节点由脚本创建。编辑器未运行时只看到 Main；运行后，在场景面板切到「远程」可查看完整节点。节点大致如下（重复 Label/Button 会由 Godot 自动补编号）：

```text
Main (Control，挂 main.gd)
├─ Background (ColorRect)
├─ Sidebar (ColorRect)
├─ Label（文字料理）
├─ 餐厅 / 农场 / 畜棚 (Button，三个平级节点)
├─ Restaurant (Control)
│  ├─ 标题、操作提示 (Label)
│  ├─ WorkArea (ColorRect，左区)
│  ├─ IngredientArea (ColorRect，右区)
│  ├─ 区域标题、处理工具、烹饪工具 (Label)
│  ├─ 补充食材、重置 (Button)
│  ├─ Cards (Control)
│  │  └─ Card… (PanelContainer，挂 card.gd)
│  │     └─ Label（卡片文字）
│  ├─ 状态提示 (Label)
│  └─ 卡片说明 (Label)
└─ Placeholder (Label，农场/畜棚占位内容)
```

所有卡片位置都相对于 Cards；Cards 与 Restaurant 都保持在原点，因此代码里的桌面坐标可以直接比较。

## 3. 主脚本逐段理解

### 常量和变量

`WORK_AREA` 是工具可移动的矩形，`TABLE_AREA` 是食材与成品可移动的矩形。`Rect2(x, y, 宽, 高)` 描述它们。左区约占桌面的 40%，右区约占 60%。`INGREDIENT_NAMES` 是可补充食材名单。

`cards` 数组保存桌面上的卡片，`selected_card` 保存当前正在看说明的卡片。这里没有全局管理器或事件总线。

### 创建界面

`_ready()` 在场景进入游戏时调用，先 `build_interface()` 创建控件，再 `reset_table()` 放入初始工具和食材。

`make_label()`、`make_button()`、`make_panel()` 只是重复创建节点的简短辅助函数：设置文字、位置、尺寸，然后 `add_child()` 把节点放到父节点下面。不是复杂框架。

`button.pressed.connect(add_ingredient.bind(ingredient_name))` 的意思是：按钮被点击时调用 `add_ingredient()`，并把这个按钮对应的食材名传进去。

`show_page()` 只改变餐厅和占位页的可见性，不销毁卡片，因此切换回来仍保留工作台。

### 食材数据和创建

每份食材是一个简单字典，例如 `{"name": "番茄", "process": "榨"}`。一张卡片的 `items` 是数组；只有一项就是单份食材，多项就是食材组，不需要额外的分组类。

`create_card()` 创建卡片，复制食材数据，连接单击和拖拽完成两个信号，再放进 Cards 节点和 cards 数组。`duplicate(true)` 表示连里面的字典一起复制，防止修改一份食材时误改另一份。

`add_ingredient()` 补充一份食材并找空位。`remove_card()` 从数组移除旧卡片、隐藏并延迟删除节点，避免合并后旧卡片继续挡住鼠标。

### 松手时判断目标

`on_card_dropped()` 只处理食材。用 `position + size / 2` 求卡片中心，然后用 `Rect2(...).has_point(center)` 检查它是否落进目标。

从最上层目标开始检查，命中后立即 `return`，所以一次松手只会触发一个结果。落到另一份食材时，把食材数组追加给目标，再删除被拖动的卡片。最多 6 份，防止卡片高度挤出桌面。

### 处理与烹饪

`use_tool()` 根据工具名字判断动作。切和榨只接收单份食材，修改 `process` 并刷新文字。原型保留最近一次处理：先榨再切最终算切；如果想保留处理历史，以后才需要修改这部分数据。

煮、炸、炒要求至少两份食材，直接把该组卡片的 `kind` 改成 `dish`，保存做法和标签，再刷新卡片。原食材数据仍留在卡片中，后续可用于菜谱记录。

`calculate_tags()` 是修改料理规则的主要位置：统计食材本名（不同处理状态的番茄仍算同种），出现至少两份就加一次超浓；任何一份榨过就加一次细腻；最后根据做法添加酥脆、炒制或温润。规则完全确定，没有随机评分。

### 找空位和说明

`place_near()` 每隔 24 像素检查一个候选位置，排除越界或与其他卡片重叠的位置，选离预期位置最近的一处。桌面特别拥挤时会给出提示，允许玩家手动整理或重置。

`on_card_clicked()` 对同一张卡再次单击时关闭说明；点新卡则调用 `update_info()` 显示它的规则。处理或合并后也会更新正在显示的说明。

## 4. 卡片脚本逐段理解

`kind` 决定是食材、工具还是料理；`items` 保存食材，`tags` 保存料理标签。`drag_area` 指定能拖到哪里。

`_ready()` 创建文字标签，并让文字忽略鼠标输入，确保点击由外面的卡片统一接收。

`refresh()` 根据类型调整边框、底色和文字。食材按「名字 + 处理状态」统计显示数量；料理显示未知料理和标签。`get_combined_minimum_size()` 按文字需要调整卡片大小，避免多行文字超出边框。

`_gui_input()` 只在按下卡片时记录鼠标位置和卡片原始位置，并把卡片移到最上层。

`_input()` 在按住期间持续接收移动和松手。位移超过 `DRAG_DISTANCE`（8 像素）才开始拖动，因此手抖不会立刻触发合并。拖动时位置等于「原位置 + 鼠标位移」。松开时，如果曾经拖动，就发 `dropped`；否则发 `clicked`。两个信号直接连接到主脚本，没有中间系统。

`clamp_to_area()` 用 `clampf()` 限制横纵坐标，并减去卡片自身宽高，确保整张工具卡都留在左区。

`_notification()` 在切出窗口或切换页面时取消按住状态，避免鼠标松开后卡片还跟着走。

## 5. 以后去哪里改

| 想改什么 | 修改位置 |
| --- | --- |
| 食材名称 | main.gd 顶部 INGREDIENT_NAMES；超过三种需要同时调整顶部按钮布局 |
| 初始工具与位置 | main.gd 的 reset_table() |
| 初始食材数量 | main.gd 的 reset_table() 最后的食材循环 |
| 标签规则 | main.gd 的 calculate_tags() |
| 处理规则 | main.gd 的 use_tool() |
| 卡片颜色、宽度、文字大小 | card.gd 的 refresh() |
| 单击/拖动灵敏度 | card.gd 顶部 DRAG_DISTANCE |
| 食材组上限和卡片上限 | main.gd 顶部 MAX_GROUP、MAX_CARDS |
| 区域尺寸与布局 | main.gd 顶部矩形与 build_interface()；边界和背景一起改 |
| 窗口尺寸 | project.godot 的 display 设置；当前布局按 1280×720 设计 |

## 6. 检查与下一步

开发检查用 Godot 的 `--headless --path 项目路径 --script res://test_workbench.gd` 运行，测试鼠标点击、拖动处理、组合、继续接收食材、烹饪、标签、工具边界、页面切换和重置，最后输出失败数量。

手动试玩仍建议按第一节完整做一遍，再分别试煮和炒。错误可在 Godot 下方「调试器」查看。

下一步优先改善工作台操作反馈，例如目标高亮和拆分食材组；之后再考虑菜谱记录。农场、畜棚、顾客、经济、员工和存档都没有在本次实现。
