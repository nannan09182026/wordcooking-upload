# 经营原型使用与代码说明

本轮在原来的极简后厨上增加了餐厅、农场和畜棚。用 Godot 4.6 打开 `project.godot`，按 F5 运行。当前是可玩原型，退出后不保存；所有计时仅在游戏运行时推进，切换页面不会重置或暂停生长。

## 先试玩一整天

1. 默认进入餐厅，初始 300 金币，仓库有番茄 6、鸡蛋 6、土豆 4。点击左侧「后厨」。
2. 点「备料」，取两份番茄、一份鸡蛋，再点备料收起菜单。这些食材会从仓库扣除，不再免费无限补充。
3. 回餐厅点「开始营业」，点击林小姐接单。她先要求含番茄的料理，不会提前给出喜好。
4. 回后厨，将一份番茄拖到榨上。把另一份番茄、鸡蛋拖到它上面，形成三份食材的组，再拖到炸上。
5. 得到未知料理，标签含「超浓、细腻、酥脆、酸甜、鲜香」。单击成品，再点上方「端菜」。
6. 自动回餐厅，把料理的中心拖到林小姐的文字块上松手，看到评分、反馈和小费。
7. 每隔 8 秒尝试来一位客人，最多同时 3 位。继续接单制作。暂时无法完成的订单可先选中客人，再点「退单」。再次点击客人只查看说明，不会直接退单。
8. 没有未完成客人时可点「打烊结算」，查看收入、小费、支出、工资、余额，再进入下一天。可以提前打烊，不必等到全部预计客人到齐。

端错的菜可以单击后点「退回后厨」。后厨「放回」归还选中的食材/食材组，「整理」归还全部未烹饪食材并恢复工具位置。两者都会清除处理状态，但不会退还或复制已做好的料理。

## 农场

1. 点「购买」，买小片田地（30）和种子（每份 2）。目前支持小麦、番茄、土豆。
2. 点「种植」，左侧二级栏出现种子文字块和库存数量。把种子拖到空田地，成功才扣除一份。拖空、种子不足、田里已有作物均不扣除。
3. 田地下方显示进度条，18 秒后变成「成熟的小片小麦」等名称。
4. 点击成熟田地，3 个作物文字块向四周散开，田地恢复为空。
5. 点「收集」，底部出现收集箱；逐个把作物拖进箱子，它们进入全局仓库，可去后厨备料。
6. 第 2 天起，点「升级」再选空的小片田地，花 45 变为大片田地。名称和宽度改变，每次产量从 3 增至 7。再次点升级可以取消升级选择。

农场最多 6 块田。散落作物最多 48 个；达到上限时成熟作物留在田里，先收集再收获，不会丢失。

## 畜棚

1. 初始是空白设施页。点击「建鸡舍 · 40」，右侧出现鸡舍文字块，再点击进入。
2. 内侧操作栏变为「返回、购买、投喂、收集、升级」，全局页面导航保留，便于随时回餐厅。
3. 点购买，买幼崽（15）和两份饲料（每份 2）。点投喂，将二级栏的饲料拖入右侧饲养栏。
4. 小鸡会轻微蹦跳，走向最近的饲料并吃掉，每份饲料增长一半成长值。吃两份后变为鸡。
5. 长大的鸡约 14 秒后产出一枚独立的鸡蛋文字块。后续每枚蛋需要再喂一份饲料。
6. 点收集，鸡蛋拖进底部收集箱后进入仓库，后厨可以拿取。
7. 兔舍、猪圈同样可以购买。兔、猪也吃两份饲料长大，名称显示「可出栏」；点击成熟动物出栏，动物消失并留下 3 份兔肉/猪肉，仍需拖入收集箱。
8. 第 2 天可花 45 扩建设施，容量从 3 只增至 6 只。不同设施的动物、饲料、产物分开显示与交互。

兔猪的出栏方式是原型补充规则，原文只详细规定了鸡的产蛋流程。动物没有疾病或死亡机制。

## 菜谱、定价、顾客和员工

做出的料理按食材、处理方式和烹饪方法自动记录；拖拽顺序不同不产生重复菜谱。菜谱不会自动上架，去餐厅的「菜谱」自行上架/下架。基础价是食材商店成本之和 ×2 +4，每次可调价 10%，范围 -30%～+50%。

开始营业时按上架菜谱平均涨幅决定预计客人数：原价 5 位，+20% 为 3 位，-20% 为 7 位，范围 2～8 位。高于或等于 +20% 时出现嫌贵反馈。营业中改价不修改已报价订单，影响下一次营业。客人仍指定食材，菜单用于决定食材需求和报价，不强制玩家照固定配方做菜。没有上架菜谱时允许自由探索，按上菜成品的系统基础价付费。

客人有隐藏的喜好标签，满足所点食材才允许上菜。评分为 2 + 命中喜好数量（最高 5），命中至少 2/3 时增加小费。反馈给出喜好线索；「顾客」菜单只显示通过成功匹配发现的偏好，不提前公开答案。

第 3 天早晨可以雇人：每位入职 50，每天工资 6。前台自动接单；主厨每 4 秒检查一次已接订单，用桌面已经备好的食材按上架菜谱处理和制作；传菜员负责把已有成品送给对应客人。三个岗位可分别雇用，不要求全雇。主厨缺料或没有合适上架菜谱时等待，不会从仓库偷取或凭空生产。早晨可解雇；工资不足时支付余额后员工离职。

第 2 天起可在后厨点扩建，花 60 将桌面卡片上限由 20 增至 32。食材组仍最多 6 份，避免文字块过高。

## 文件与场景树

只使用一个主场景，没有事件总线、自动加载单例或复杂继承。

```text
Main（Control，main.gd）
├─ 背景、侧边栏、日期/金币、提示文字
├─ Restaurant（Control，dining.gd）
│  ├─ 营业、菜谱、顾客、员工、退单、退菜按钮
│  └─ 顾客与料理卡片
├─ Kitchen（Control，kitchen.gd）
│  ├─ 备料、放回、端菜、整理、扩建按钮
│  ├─ Cards（工具、食材组、料理）
│  └─ PantryMenu（仓库备料二级菜单）
├─ Farm（Control，farm.gd）
│  ├─ 购买菜单、种子菜单
│  └─ 田地、进度条、散落作物、收集箱
├─ Barn（Control，barn.gd）
│  ├─ 设施页（鸡舍/兔舍/猪圈）
│  └─ 饲养页（购买/投喂、动物、饲料、产物、收集箱）
└─ ManagementMenu（可滚动的仓库/商店/菜谱/员工/结算窗口）
```

节点由简单的 `new()` 和 `add_child()` 创建。编辑器静态场景只显示 Main；运行后在「远程」场景树查看它们。

| 文件 | 职责与主要修改位置 |
| --- | --- |
| main.gd | 日期、金币、仓库、菜单；PRICES 改价格，BASE_TAGS 改食材标签，inventory 改初始库存 |
| kitchen.gd | 从原 main.gd 拆出的料理台；calculate_tags 改标签，use_tool 改处理，auto_cook 改员工制作 |
| farm.gd | GROW_SECONDS 改成长时间；buy_plot 改地价，harvest 改产量，upgrade_plot 改升级 |
| barn.gd | EGG_SECONDS 改产蛋时间；eat 改成长，advance 改移动速度，PRODUCTS 改产物 |
| dining.gd | PEOPLE 改顾客隐藏偏好，open_day 改来客量，serve 改评分小费，close_day 改结算 |
| card.gd | 所有文字块的外观、点击/拖动、进度条；refresh 改尺寸颜色，DRAG_DISTANCE 改拖动阈值 |
| test_game.gd | 自动检查脚本；测试会使用自己的测试状态，不会改游戏初始配置 |

## 关键代码分段解释

### main.gd

`pages` 字典保存四个页面。`show_page()` 只改变 `visible`，所以切走后田地、动物、订单仍保留。各页面的 `game` 指向 Main，可直接调用 `game.spend()` 或访问 `game.inventory`，没有额外消息系统。

`spend()` 先检查余额，再扣钱并记录支出；余额不足返回 false，调用者立即停止购买。`record_recipe()` 把食材与处理状态排序形成菜谱标识，避免同一配方重复记录。`next_day()` 只在夜晚允许执行，增加一天并清空每日统计，防止重复点击刷日期。

### kitchen.gd

`add_ingredient()` 检查库存和桌面容量，扣一份库存后创建卡片。`on_card_dropped()` 用卡片中心检测目标：工具调用 `use_tool()`，食材则合并数组。`calculate_tags()` 先统计同种食材、榨汁状态和做法，再加入食材基础标签，并避免重复。

`carry_selected()` 先确认餐厅传菜台有空位，再复制料理数据到餐厅并删除后厨卡片，保证只有一份。`auto_cook()` 先找齐完整菜谱需要的食材，找不齐就不扣除；找齐才统一扣除并生成料理。

### farm.gd

每块地的 `data` 字典保存 crop、elapsed、large，分别表示种的作物、成长秒数和是否大片。`drop_seed()` 检查种子卡片中心是否落在田地内，`plant()` 确认空地和库存后才扣种子。

`advance(delta)` 累计秒数，`update_plot()` 更新文字与进度。`harvest()` 把一个成熟状态变成若干独立产物卡，使用 Tween 在 0.3 秒内向田地周围移动，再清空田地。`drop_produce()` 只在收集箱打开且命中时加库存、删卡片。

### barn.gd

`built`、`upgraded` 记录每种设施。`enter_pen()` 选择当前动物类型并隐藏其他类型的对象。动物的数据里有 growth（0～2）、meal（是否吃过产蛋所需饲料）、egg_time（产蛋计时）。

`advance()` 每帧找最近同类型饲料，用 `move_toward()` 靠近，距离足够近就调用 `eat()`。吃掉饲料会立即从 foods 数组删除，所以两只动物不会吃掉同一份。位置上的小幅正弦变化产生蹦跳感。成年鸡的计时结束生成蛋；兔猪点击出栏后移除本体并生成肉。所有产物统一走收集箱流程。

### dining.gd

`spawn_guest()` 为客人生成食材要求，但把 likes 留在内部。`accept_order()` 将文字更新为食材需求。`serve()` 先检查已接单、菜里含指定食材，再计算命中标签、星级、小费和收入，最后删除客人及料理，防止重复领取。

`run_staff()` 每 4 秒检查订单，只调用已有的接单、做菜、上菜函数，人工和员工遵守同一套扣料和评分规则。`close_day()` 拒绝仍有顾客时结算，进入夜晚后只扣一次工资。`return_dish()` 允许将选中成品搬回后厨，源卡片删除，避免复制。

### card.gd

原来的 8 像素拖动阈值保留。新增 caption 用于土地、动物、种子等文字；data 保存这些卡片自己的简单字典；movable 控制田地、设施、顾客能否移动；progress 为 -1 时不显示进度，否则显示 0～1 的完成比例。每种玩法仍写在对应页面脚本中，卡片本身只管理显示和鼠标。

## 验证方式

自动检查通过 Godot 运行 `test_game.gd`，模拟鼠标按下、移动和松开。生长和员工计时使用 advance() 加速，不必真的等待多个游戏日。测试覆盖正常路径、错误食材、缺钱、无种子、未接单、页面切换中断拖动、重复结算、菜谱去重、库存扣除、分组/设施上限等。

手动请至少按本说明完成一次做菜上菜、一次小麦种植收集和一次小鸡喂养产蛋。实际画面与逐条结果见同目录预览图和 `checks.log`。完整需求对照见《需求核对与验证.md》。

下一步建议先试玩资源消耗与来客节奏，再调成长时间、购买价格和收益；之后再加入存档。当前数值为原型测试值，不是经过长期验证的平衡方案。
